# Notebook Guidelines

If you wish to contribute Notebooks to the GeoLab Community Library, we ask that they meet certain standards for readability and usability. 

## Contents
1. Geophysics-related
2. Use data from the NSF National Geophysical Facility Archive
    a. Datasets should be extensible -- ie, another user could swap in data from a different network, station, or time period, and still expect the code to work.
3. A README file is strongly encouraged, especially for projects that contain multiple files or specific run-orders. 


## Formatting
1. The code contains sufficient comments and expository text in markdown cells for a user unfamiliar with the workflow to be able to follow. 
2. If there are multiple notebooks designed to be run in a particular order, add numbering to the file names. 

## Maintenance
1. Your notebook must specify a maintainer and contact info.  Users who encounter problems with a notebook are encouraged to contact the maintainer and/or raise an issue in that project's github repository. EarthScope is not responsible for keeping code up to date or fixing bugs identified by the community.
2. Projects will be reviewed by EarthScope staff on an annual basis. Projects which no longer run properly (due to package deprecations, etc) will be flagged. Maintainers will be contacted and if the issues are not resolved, the project will be archived.
